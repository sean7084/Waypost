# API Documentation - Waypost

**Base URL:** `http://127.0.0.1:8000/api/v1/` (development)
**Framework:** Django REST Framework (DRF)
**Last verified against code:** September 6, 2026

> ⚠️ **Scope note:** This REST API currently covers **asset, company, location, and user management only**. Quotations, deliveries, invoices, products, purchases, and reports are **not** exposed via REST — they are server-rendered HTML views (see [`WORKFLOW_GUIDE.md`](WORKFLOW_GUIDE.md)). Do not assume `/api/v1/quotations/` etc. exist.

## Overview

The API is generated by a DRF `DefaultRouter` (see `api/urls.py`). Registered resources:

| Resource | Endpoint | Write access |
|----------|----------|--------------|
| Users | `/api/v1/users/` | Read-only |
| Companies | `/api/v1/companies/` | Create = superadmin only |
| Divisions | `/api/v1/divisions/` | Full CRUD |
| Locations | `/api/v1/locations/` | Full CRUD |
| Categories | `/api/v1/categories/` | Full CRUD |
| Brands | `/api/v1/brands/` | Full CRUD |
| Models | `/api/v1/models/` | Full CRUD |
| Assets | `/api/v1/assets/` | Full CRUD |
| Assignments | `/api/v1/assignments/` | Full CRUD |
| Maintenance | `/api/v1/maintenance/` | Full CRUD |
| Inspections | `/api/v1/inspections/` | Kering store inspection (see `docs/MINIPROGRAM_SPEC.md`) |
| WeChat auth | `/api/v1/auth/wechat/{bind,login}/`, `/api/v1/auth/token/refresh/` | Mini-program login (JWT) |

A browsable API root is available at `/api/v1/` (HTML) when authenticated, and an internal endpoint index page at `/docs/`.

## Authentication

The API accepts two schemes (`settings.REST_FRAMEWORK['DEFAULT_AUTHENTICATION_CLASSES']`):

1. **JWT bearer** (`rest_framework_simplejwt`) — used by the WeChat mini program.
2. **DRF `SessionAuthentication`** — used by the web/browsable API (cookie login).

All endpoints require `IsAuthenticated`.

### JWT (mini program)

The mini program authenticates via WeChat `jscode2session` and receives SimpleJWT
access/refresh tokens (see `docs/MINIPROGRAM_SPEC.md` and ADR-0011):

- `POST /api/v1/auth/wechat/bind/` `{code, username, password}` — first launch: binds
  the WeChat openid to a staff `User` and returns `{access, refresh, user}`.
- `POST /api/v1/auth/wechat/login/` `{code}` — later launches: returns
  `{bound, access, refresh, user}` (`bound:false` when the openid is not yet linked).
- `POST /api/v1/auth/token/refresh/` `{refresh}` → `{access}`.

Send the access token on every request:

```http
Authorization: Bearer <access_token>
Content-Type: application/json
```

JWT-authenticated requests do **not** require a CSRF token.

### Session (web) — CSRF requirement

Because session authentication is also enabled, **unsafe methods** (`POST`, `PUT`,
`PATCH`, `DELETE`) made with a session cookie require a valid **CSRF token**. Send the
`X-CSRFToken` header with the value of the `csrftoken` cookie, and include `Referer`
for HTTPS.

```http
Cookie: sessionid=<session_id>; csrftoken=<csrf_token>
X-CSRFToken: <csrf_token>
Content-Type: application/json
```

## Pagination, Filtering & Ordering

- **Pagination:** `PageNumberPagination`, **page size 20**. Use `?page=N`.

  ```json
  {
    "count": 137,
    "next": "http://127.0.0.1:8000/api/v1/assets/?page=2",
    "previous": null,
    "results": [ /* ... */ ]
  }
  ```

- **Search:** `?search=<term>` on resources that define `search_fields` (see each resource).
- **Ordering:** `?ordering=<field>` (prefix `-` for descending) on resources that define `ordering_fields`.

## Resources

### Assets

`/api/v1/assets/` — full CRUD. List responses use a lightweight serializer; detail responses use the full serializer.

**Query filters:** `status`, `category`, `brand`, `company`, `location`, `division`, `assigned_to`, `barcode`, `serial_number`
**Search fields:** `asset_number`, `serial_number`, `barcode`, `description`
**Ordering fields:** `asset_number`, `created_at`, `updated_at`, `category__name`, `brand__name`, `status` (default `-created_at`)

**List item fields (`AssetListSerializer`):**
`id`, `asset_number`, `serial_number`, `barcode`, `category_name`, `brand_name`, `status`, `status_display`, `condition`, `condition_display`, `company`, `assigned_to`, `location`

**Detail fields (`AssetSerializer`):**
`id`, `asset_number`, `description`, `category`, `category_name`, `brand`, `brand_name`, `model`, `model_name`, `serial_number`, `barcode`, `company`, `company_name`, `division`, `division_name`, `assigned_to`, `assigned_to_name`, `location`, `location_name`, `current_location`, `status`, `condition`, `purchase_price`, `current_value`, `purchase_date`, `warranty_start_date`, `warranty_end_date`, `warranty_provider`, `photo`, `notes`, `created_by`, `created_by_name`, `created_at`, `updated_at`, `last_audit_date`

**Custom actions:**

| Method | Endpoint | Purpose |
|--------|----------|---------|
| GET | `/api/v1/assets/by_barcode/?barcode=<code>` | Look up a single asset by barcode |
| GET | `/api/v1/assets/by_serial/?serial=<serial>` | Look up a single asset by serial number |
| GET | `/api/v1/assets/{id}/assignments/` | Assignment history for an asset |
| GET | `/api/v1/assets/{id}/maintenance/` | Maintenance history for an asset |

`by_barcode` / `by_serial` return `400` if the query parameter is missing and `404` if no match is found.

> Assets, categories, brands, models, companies, and locations use **UUID** primary keys.

## Permissions & Role Scoping

All endpoints require `IsAuthenticated`. Querysets are additionally scoped by role (`accounts.models.User` helpers):

| Role | Visibility |
|------|-----------|
| **Superadmin** | All records |
| **IT Administrator** | Records within their managed company/divisions/locations |
| **Viewer Admin** | Records reachable via their managed locations |
| **Other** | Minimal or none (e.g., users see only themselves) |

Write operations are permitted for authenticated users on most resources, **except**:
- **Company creation** — superadmin only.
- **Users** — read-only for everyone.

Assets are scoped via `user.get_accessible_assets()`.

## Error Handling

The API uses **standard DRF error responses** (not a custom envelope).

| Code | Meaning |
|------|---------|
| 200 | Success |
| 201 | Created |
| 400 | Validation error (field-level) |
| 403 | Not authenticated / permission denied |
| 404 | Not found |
| 405 | Method not allowed |

**Validation error (400):** keyed by field.
```json
{
  "serial_number": ["asset with this serial number already exists."],
  "category": ["This field is required."]
}
```

**Permission / auth error (403):**
```json
{ "detail": "Authentication credentials were not provided." }
```

**Not found (404):**
```json
{ "detail": "Not found." }
```

## Testing the API

### Django test client (session auth)

```python
from django.test import TestCase
from rest_framework import status
from django.contrib.auth import get_user_model

User = get_user_model()

class AssetAPITest(TestCase):
    def setUp(self):
        self.user = User.objects.create_user(username='test', password='pass')
        self.client.force_login(self.user)  # establishes session auth

    def test_list_assets(self):
        response = self.client.get('/api/v1/assets/')
        self.assertEqual(response.status_code, status.HTTP_200_OK)
```

### curl (session cookie)

```bash
# 1) Log in via the browser or the login form to obtain sessionid + csrftoken cookies.
# 2) Call the API reusing those cookies:
curl http://127.0.0.1:8000/api/v1/assets/ \
  -H "Cookie: sessionid=<SESSION_ID>; csrftoken=<CSRF_TOKEN>"

# Write operations also need the CSRF header:
curl -X POST http://127.0.0.1:8000/api/v1/brands/ \
  -H "Cookie: sessionid=<SESSION_ID>; csrftoken=<CSRF_TOKEN>" \
  -H "X-CSRFToken: <CSRF_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"name": "Dell", "code": "DELL"}'
```

> Because there is no token-auth endpoint, headless/CI clients must establish a Django session first (e.g., via `django.test.Client` or a scripted login that handles CSRF).

## Known Gaps & Planned Work

| Gap | Detail |
|-----|--------|
| No token/JWT auth | Only session auth is configured; machine-to-machine clients need a token scheme (e.g., DRF `TokenAuthentication` or SimpleJWT). |
| No order-management API | Quotations, deliveries, invoices, products, purchases, reports are HTML-only. Exposing them via REST is future work. |
| `IsSuperadminOrReadOnly` unused | Defined in `api/views.py` but no viewset applies it; write gating relies on queryset scoping + `perform_create` checks. |
